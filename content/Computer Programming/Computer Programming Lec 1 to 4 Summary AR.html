1. مقدمة إلى البرمجة بلغة C++ (Introduction to C++)

هيكل البرنامج، المتغيرات، الثوابت، قواعد تسمية المعرفات، أنواع البيانات، ومجاري الإدخال والإخراج القياسية.

# الهيكل_البنائي # التعليقات # المتغيرات_والثوابت # أنواع_البيانات_والإدخال
فخاخ امتحانية شائعة // نقاط هامة جداً: 1. متغيرات الثوابت const يجب تهيئتها وإعطاؤها قيمة لحظة الإعلان عنها مباشرة؛ فكتابة const int x; x = 5; تؤدي إلى خطأ ترجمة (Compiler Error).
2. المتغيرات التي تبدأ بأرقام (مثل 10rate) أو تحتوي على شرطة عادية (shoubra-faculty) أو مسافات هي أسماء غير صالحة برمجياً (Invalid Identifiers).

1.1 الهيكل البنائي والتشريحي لبرنامج C++

يتكون أي برنامج قياسي مكتوب بلغة C++ من مكونات بنائية أساسية لا غنى عنها:

  • توجيهات ما قبل المعالجة (Preprocessor Directives): أسطر تبدأ بعلامة #، مثل #include <iostream>، ترشد المعالج المسبق لتضمين ترويسات الإدخال والإخراج القياسية قبل الترجمة.
  • الدالة الرئيسية main(): نقطة انطلاق وبدء تنفيذ البرنامج الإلزامية التي يبدأ التحكم عندها دائماً، ويجب أن تُرجع قيمة عددية صحيحة (int).
  • جملة الإرجاع return 0;: تُنهي تنفيذ الدالة الرئيسية وترسل إشارة إلى نظام التشغيل بأن البرنامج انتهى بنجاح وبشكل طبيعي.
  • الفاصلة المنقوطة ;: علامة الترقيم الإلزامية التي تختم كل جملة برمجية تنفيذية (Statement).
SAMPLE CODE // FIRST PROGRAM
welcome.cpp 
#include <iostream>
using namespace std;

int main() {
    cout << "Welcome to C++!\n";
    return 0;
}

1.2 التعليقات في C++ (Comments)

التعليقات عبارة عن جمل غير تنفيذية يتجاهلها المترجم كلياً، وتُستخدم فقط للتوثيق وتسهيل قراءة الكود:

  • تعليق السطر الواحد (Single-Line Comment): يبدأ بالعلامة // ويتجاهل المترجم ما تبقى من ذلك السطر.
  • التعليق متعدد الأسطر (Block Comment): يبدأ بالعلامة /* وينتهي بالعلامة */، ويمكن أن يمتد لعدة أسطر.

1.3 المتغيرات، المعرفات، والثوابت (Variables, Identifiers & Constants)

المتغير (Variable): موقع محجوز في ذاكرة الحاسوب لتخزين قيمة يمكن تعديلها وتغييرها أثناء تنفيذ البرنامج.

قواعد تسمية المعرفات (Identifier Naming Rules):

  1. تتكون فقط من الحروف (كبيرة وصغيرة)، الأرقام، والشرطة السفلية _.
  2. يجب أن تبدأ بحرف أو بشرطة سفلية (ممنوع منعاً باتاً أن تبدأ برقم).
  3. لا يمكن أن تحتوي على مسافات فارغة أو رموز وعلامات خاصة (#, -, !, $, %).
  4. لا يجوز أن تكون كلمة محجوزة من الكلمات المفتاحية للغة (int, class, cin, return).

طرق الإعلان عن الثوابت (Constants):

  • باستخدام المعالج المسبق: #define PI 3.14 (بدون فاصلة منقوطة وبدون علامة =).
  • باستخدام الكلمة المفتاحية: const float PI = 3.14; (التهيئة بقيمة أولية إلزامية عند التعريف).

1.4 أنواع البيانات ومجاري الإدخال والإخراج القياسية

فئة النوع الكلمات المفتاحية الوصف والاستخدام
الأعداد الصحيحة short, int, long أعداد صحيحة بدون أجزاء كسرية أو فواصل عشرية.
الأعداد العشرية (الحقيقية) float, double, long double أعداد بكسور عشرية وبمستويات دقة متفاوتة.
الحروف char حرف واحد أو رمز فردي محاط بعلامتي اقتباس مفردتين مثل 'A'.
السلاسل النصية string سلسلة من المحارف والكلمات والجمل النصية.
القيم المنطقية bool قيم الصواب والخطأ المنطقية: true (تُعامل كرقم 1) أو false (تُعامل كرقم 0).

إعادة تسمية الأنواع باستخدام typedef:

typedef int number;
number distance = 150; // المتغير 'distance' نوعه في الأصل عدد صحيح int

معاملات التدفق ورموز الهروب (Escape Sequences):

  • cout << : معامل الإقحام (Insertion Operator) لعرض وطباعة البيانات على الشاشة.
  • cin >> : معامل الاستخراج (Extraction Operator) لقراءة الإدخال من لوحة المفاتيح وتخزينه في المتغيرات.
  • \n : محرف سطر جديد (Newline).
  • \t : مسافة جدولة أفقية (Tab stop).
  • endl : إدراج سطر جديد مع تفريغ الذاكرة المؤقتة لمجرى الإخراج (Flushes output buffer).

2. المعاملات والتعبيرات في C++ (Operators & Expressions)

أسبقية العمليات الحسابية، التراكم والإسناد، الزيادة والنقصان، المعاملات المنطقية، ومفهوم Lvalues مقابل Rvalues.

# أسبقية_المعاملات # الزيادة_والنقصان # العمليات_المنطقية # فخ_المساواة # Lvalues_مقابل_Rvalues
فخاخ امتحانية شائعة // نقاط هامة جداً: 1. حاصل قسمة عددين صحيحين 31 / 3 ينتج 10 فقط (مع بتر وحذف الأرقام العشرية بالكامل)، وليس 10.333!
2. معامل باقي القسمة % يعمل فقط وحصرياً مع الأعداد الصحيحة؛ وتطبيقه على أعداد كسرية يؤدي إلى خطأ ترجمة فوري.

2.1 المعاملات الحسابية وقواعد الأسبقية (Precedence)

المعاملات الحسابية القياسية: الجمع (+)، الطرح (-)، الضرب (*)، القسمة (/)، وباقي القسمة (%):

تسلسل ترتيب أسبقية العمليات:

  1. الأقواس (): تُنفذ أولاً دائماً، بدءاً من الأقواس الداخلية نحو الخارجية.
  2. عمليات الضرب والقسمة وباقي القسمة (*, /, %): تُنفذ ثانياً، من اليسار إلى اليمين.
  3. عمليات الجمع والطرح (+, -): تُنفذ أخيراً، من اليسار إلى اليمين.

2.2 معاملات الزيادة والنقصان (Increment & Decrement)

اختصارات الإسناد التراكمي: c += 3 تكافئ تماماً c = c + 3.

الفرق بين الزيادة القبلية والزيادة البعدية (Prefix vs Postfix):

  • الزيادة القبلية (++x): يُزاد المتغير أولاً، ثم تُستخدم القيمة الجديدة المحدثة في باقي أجزاء التعبير الحالي.
  • الزيادة البعدية (x++): تُستخدم القيمة الحالية أولاً في التعبير، ثم تتم زيادة المتغير بواحد بعد الانتهاء.
  • عند كتابة المتغير كجملة برمجية مستقلة بذاتها (مثل ++c; مقابل c++;)، يعطي الاثنان نفس النتيجة النهائية تماماً.
TRACE EXAMPLE // PRE VS POST
inc_trace.cpp 
#include <iostream>
using namespace std;

int main() {
    int c = 5;
    cout << ++c << endl; // يطبع 6 (تتم الزيادة فوراً قبل الطباعة)
    cout << c++ << endl; // يطبع 6 (تُطبع القيمة الحالية ثم تصبح c = 7)
    cout << c << endl;   // يطبع 7
    return 0;
}

2.3 معاملات المقارنة والمعاملات المنطقية (Relational & Logical)

تنتج معاملات المقارنة قيماً منطقية: إما صواب true (1) أو خطأ false (0):

  • المقارنة: >, <, >=, <=, ==, !=.
  • المنطقية: && (و - AND)، || (أو - OR)، ! (نفي - NOT).

تقييم الدائرة القصيرة (Short-Circuit Evaluation):

تقوم C++ بتحسين التقييم المنطقي عبر التوقف مبكراً بمجرد ضمان النتيجة النهائية وحسمها قطيعاً:

  • في معامل &&: إذا كان الطرف الأيسر false، لا يتم تقييم الطرف الأيمن مطلقاً (لأن الناتج الكلي حتماً false).
  • في معامل ||: إذا كان الطرف الأيسر true، لا يتم تقييم الطرف الأيمن مطلقاً (لأن الناتج الكلي حتماً true).

2.4 الخلط الكارثي بين علامة المساواة (==) والإسناد (=)

خطأ منطقي فادح وصامت:
كتابة if (payCode = 4) بدلاً من if (payCode == 4) تُسند القيمة 4 إلى payCode. ولأن القيمة 4 غير صفرية، تعتبرها C++ قيمة صائبة (True) دائماً، مما يؤدي لتنفيذ جسم الشرط دون أي تحذير من المترجم!

2.5 مفهوم Lvalues مقابل Rvalues

  • قيم الطرف الأيسر (Lvalues): تعبيرات يمكن أن تقع على الطرف الأيسر من معادلة الإسناد. وهي تشير إلى مواقع ذاكرة فعلية ومستمرة قابلة للتعديل وتملك عنواناً (مثل المتغيرات: x = 4;).
  • قيم الطرف الأيمن (Rvalues): تعبيرات يمكن أن تقع فقط على الطرف الأيمن من معادلة الإسناد. وهي تمثل قيماً مؤقتة أو حسابات لحظية أو ثوابت عددية (مثل الأرقام: لا يمكن كتابة 4 = x;).
  • القاعدة الذهبية: يمكن استخدام Lvalues كـ Rvalues، لكن لا يمكن استخدام Rvalues كـ Lvalues أبداً!

3. هياكل التحكم والاختيار (Control Structures: Selection)

منطق اتخاذ القرار: if، if/else، المعامل الثلاثي، التفرع المتداخل، بنية switch، وتصنيف الأخطاء البرمجية.

# if_و_ifelse # المعامل_الثلاثي # تصنيف_الأخطاء # بنية_switch
فخاخ امتحانية شائعة // نقاط هامة جداً: 1. في جملة switch، المتغير أو التعبير المفحوص يجب أن يكون من نوع صحيح متكامل (int أو char فقط)، ولا يقبل الأنواع العشرية float أو double أو السلاسل النصية string.
2. نسيان جملة break يتسبب في ظاهرة السقوط الحر (Fall-through)، مما يؤدي لتنفيذ جميع الحالات التالية دون فحص شروطها حتى الوصول لأول break.

3.1 هياكل الاختيار if و if/else

في لغة C++، أي قيمة غير صفرية تُعامل كـ True (صواب)، والقيمة صفر وحدها تُعامل كـ False (خطأ).

الجمل المركبة والأقواس المعقوفة (Compound Statements):
عند احتواء كتلة if أو else على أكثر من جملة برمجية واحدة، يجب حصرها إلزامياً داخل أقواس معقوفة { }. فبدون الأقواس، تنتمي الجملة الأولى فقط للشرط، بينما تُنفذ الجمل اللاحقة في جميع الأحوال دون قيد.

3.2 المعامل الشرطي الثلاثي (Ternary Operator ?:)

صيغة مختصرة بديلة لجمل if/else البسيطة: الشرط ? القيمة_إذا_تحقق : القيمة_إذا_لم_يتحقق;

cout << (grade >= 60 ? "Passed" : "Failed");

3.3 التصنيف الشامل لأنواع الأخطاء البرمجية

فئة الخطأ وقت الاكتشاف النتيجة والسلوك أمثلة شائعة
أخطاء الصياغة (Syntax Errors) وقت الترجمة (Compile Time) يكتشفها المترجم؛ يفشل البرنامج في التحول إلى ملف تنفيذي ويعطي رسائل خطأ. نسيان الفاصلة المنقوطة ;، أخطاء إملائية في الكلمات المفتاحية (cot)، أقواس غير مغلقة.
أخطاء منطقية غير قاتلة (Non-fatal Logic Errors) وقت التشغيل (Runtime) يعمل البرنامج حتى نهايته بشكل طبيعي، ولكنه يُخرج نتائج وحسابات خاطئة أو غير مقصودة. استخدام = بدلاً من ==، أو حساب المتوسط بشكل خاطئ a+b/2 بدل (a+b)/2.
أخطاء منطقية قاتلة (Fatal Logic Errors) وقت التشغيل (Runtime) يتوقف البرنامج عن العمل فجأة وينهار (Crashes) قبل إتمام باقي الأوامر. القسمة على صفر (x / 0)، أو استدعاء تكراري لانهائي يستنزف مساحة الذاكرة (Stack Overflow).

3.4 بنية الاختيار المتعدد switch

تُعد البديل الأنسب والأنظف عند مقارنة قيمة متغير صحيح واحد مقابل عدة قيم ثابتة بدلاً من سلاسل else if الطويلة:

COMPLETE EXAMPLE // DAYS IN MONTH WITH LEAP YEAR
days_in_month.cpp 
#include <iostream>
using namespace std;

int main() {
    int month, year;
    cout << "Enter month number (1-12): ";
    cin >> month;

    switch (month) {
        case 1: case 3: case 5: case 7:
        case 8: case 10: case 12:
            cout << "31 days" << endl;
            break;
        case 4: case 6: case 9: case 11:
            cout << "30 days" << endl;
            break;
        case 2:
            cout << "Enter year: ";
            cin >> year;
            if ((year % 4 == 0 && year % 100 != 0) || (year % 400 == 0))
                cout << "29 days (Leap year)" << endl;
            else
                cout << "28 days (Normal year)" << endl;
            break;
        default:
            cout << "Invalid month number!" << endl;
    }
    return 0;
}

4. هياكل التحكم والتكرار (Iteration & Loops)

بُنى التكرار: for، while، do/while، المقارنة بين break و continue، وأنماط الحلقات التكرارية المتداخلة.

# أنواع_الحلقات # حلقة_for # حلقة_while # حلقة_do_while # break_مقابل_continue # الحلقات_المتداخلة
فخاخ امتحانية شائعة // خاصة بحلقات التكرار: 1. الفاصلة المنقوطة الخاطئة: كتابة for(int i=0; i<5; i++); { cout << i; } تُنشئ حلقة بجسم فارغ! تدور الحلقة 5 مرات دون فعل شيء، ثم تُنفذ الأقواس مرة واحدة فقط بقيمة i = 5.
2. فاصلة do/while المنقوطة: بخلاف حلقاتي while و for، فإن حلقة do { ... } while(cond); تتطلب إلزامياً فاصلة منقوطة في نهايتها.
3. أمر continue في حلقة while: تنفيذ continue داخل حلقة while يقفز مباشرة إلى فحص الشرط في الأعلى، مما يتجاوز خطوة تحديث العداد في الأسفل، ويؤدي غالباً إلى حلقة تكرار لانهائية (Infinite Loop)!

4.1 بُنى التكرار الثلاث في C++

تتيح الحلقات التكرارية إعادة تنفيذ التعليمات طالما ظل شرط الاستمرارية صائباً (true):

  • حلقة for: تكرار مضبوط بالعداد (Counter-controlled)، وهي الأنسب عندما يكون عدد مرات التكرار معلوماً بدقة مسبقاً قبل بدء الحلقة.
  • حلقة while: تكرار مضبوط بالشرط يفحص الشرط قبل كل دورة (Pre-test)، ويمكن ألا تُنفذ ولا مرة واحدة إطلاقاً (0 مرات).
  • حلقة do/while: تكرار مفحوص لاحقاً (Post-test) يفحص شرط الاستمرار بعد تنفيذ جسم الحلقة، مما يضمن تنفيذها مرة واحدة على الأقل.

4.2 بنية حلقة التكرار for

تجمع صيغة for القياسية بين التهيئة الأولية، فحص شرط الاستمرار، وخطوة التحديث داخل سطر واحد منظم:

for ( ForInit ; LoopContinuationTest ; PostExpression ) {
    ActionStatements;
}

ترتيب خطوات التنفيذ في حلقة for:

  1. التهيئة الأولية (ForInit): تُنفذ مرة واحدة فقط عند بداية انطلاق الحلقة.
  2. فحص الشرط (ForExpr): يُفحص قبل بداية كل دورة؛ إذا كان true يُنفذ جسم الحلقة، وإذا كان false تنتهي الحلقة فوراً.
  3. تنفيذ الأوامر (Action Body): الأوامر البرمجية داخل جسم الحلقة.
  4. تعبير التحديث (PostExpr): يُنفذ بعد اكتمال جسم الحلقة (عادة زيادة أو نقصان العداد).
  5. يعود المسار إلى الخطوة رقم 2 وتتكرر العملية.
معامل الفاصلة في حلقة for:
يمكن استخدام الفاصلة العادية لدمج عدة متغيرات في خطوتي التهيئة والتحديث:
for (int i = 0, j = 0; j + i <= 10; j++, i++)
SAMPLE CODE // FOR LOOP SUMMATIONS
for_examples.cpp 
#include <iostream>
using namespace std;

int main() {
    // 1. جمع الأعداد الزوجية من 0 حتى 100
    int evenSum = 0;
    for (int i = 0; i <= 100; i += 2) {
        evenSum += i;
    }
    cout << "Even Sum = " << evenSum << endl; // الناتج: 2550

    // 2. طباعة حرف محدد N من المرات
    char ch = '*';
    int n = 5;
    for (int i = 0; i < n; i++) {
        cout << ch;
    }
    cout << endl;
    return 0;
}

4.3 بنية حلقة التكرار while

تستمر حلقة while في التكرار طالما كان شرط الاستمرار صائباً (true). وإذا كان الشرط خاطئاً من البداية، فلن يُنفذ جسم الحلقة إطلاقاً (0 مرات).

SAMPLE CODE // WHILE LOOP FACTORIAL & ACCUMULATOR
factorial.cpp 
#include <iostream>
using namespace std;

int main() {
    int n, fact = 1;
    cout << "Enter a positive integer: ";
    cin >> n;

    int temp = n;
    while (temp > 0) {
        fact = fact * temp;
        temp--;
    }
    cout << "Factorial of " << n << " is " << fact << endl;
    return 0;
}
تحويل حلقة for إلى حلقة while:
كل حلقة for (init; cond; inc) { body; } يمكن كتابتها بدقة هكذا:
init; while (cond) { body; inc; }

4.4 بنية حلقة التكرار do/while

تفحص حلقة do/while شرطها بعد تنفيذ الأوامر، ولذلك فهي تضمن التنفيذ مرة واحدة على الأقل حتى وإن كان الشرط خاطئاً من البداية.

do {
    statement(s);
} while ( condition ); // انتبه للفاصلة المنقوطة الإلزامية في النهاية!
SAMPLE CODE // DO-WHILE COUNTER
dowhile_counter.cpp 
#include <iostream>
using namespace std;

int main() {
    int counter = 1;
    do {
        cout << counter << " ";
    } while (++counter <= 10);
    cout << endl;
    return 0;
}

4.5 أوامر القفز: break مقابل continue

جملة break

تُسبب خروجاً فورياً من حلقة while أو for أو do/while أو هيكل switch، وينتقل التنفيذ إلى أول جملة تلي الهيكل مباشرة.

جملة continue

تقوم بتخطي باقي التعليمات المتبقية في الدورة الحالية فقط، وتنتقل فوراً إلى الدورة التالية من الحلقة التكرارية.

الفارق الجوهري في سلوك continue:

  • في حلقة for: تقوم continue بتنفيذ خطوة التحديث/الزيادة أولاً، ثم تنتقل لفحص شرط الاستمرار.
  • في حلقتي while و do/while: تقفز continue مباشرة لفحص شرط الدورة متجاوزة أي خطوة لتحديث العداد بأسفل الحلقة.
SAMPLE CODE // BREAK AND CONTINUE IN ACTION
jump_statements.cpp 
#include <iostream>
using namespace std;

int main() {
    // 1. استخدام break: إنهاء مبكر عند إدخال المستخدم للرقم 0
    int sum = 0, val;
    for (int i = 0; i < 5; i++) {
        cin >> val;
        if (val == 0) break; // الخروج الفوري من الحلقة
        sum += val;
    }

    // 2. استخدام continue: تخطي الأرقام التي تقبل القسمة على 4
    for (int count = 0; count <= 12; ++count) {
        if (count % 4 == 0) continue; // تخطي مضاعفات الرقم 4
        cout << count << " ";         // يطبع: 1 2 3 5 6 7 9 10 11
    }
    cout << endl;
    return 0;
}

6. ملخص أنواع الأخطاء البرمجية ومصطلحات الامتحان

  • أخطاء قواعدية (Syntax Errors): يكتشفها المترجم في مرحلة الترجمة (Compile-time)، وتمنع بناء الملف التنفيذي تماماً (مثل نسيان الفواصل المنقوطة والأخطاء الإملائية).
  • أخطاء منطقية غير قاتلة (Non-Fatal Logic Errors): تحدث أثناء التشغيل (Runtime)؛ يكتمل البرنامج ولكنه ينتج مخرجات خاطئة (مثل كتابة if(a = 4)).
  • أخطاء منطقية قاتلة (Fatal Logic Errors): تحدث أثناء التشغيل (Runtime)؛ ينهار البرنامج ويتوقف فجأة (مثل القسمة على صفر).
  • Lvalue مقابل Rvalue: الـ Lvalues تقع يسار علامة التساوي وتملك عنواناً دائماً بالذاكرة وتقبل التعديل. الـ Rvalues تقع يميناً وتمثل قيماً لحظية أو ثوابت. يمكن للـ Lvalue أن يعمل كـ Rvalue ولكن ليس العكس!
