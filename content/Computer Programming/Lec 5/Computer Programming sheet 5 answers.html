المسألة / القاعدة الشرط البرمجي الحاسم (Core Condition) السر الفني والغرض في الامتحان
1. شطرنج التناوب (X / O) if ((row + col) % 2 == 0) cout << 'X'; else cout << 'O'; جمع الإحداثيات يبدأ بـ 0 (زوجي لـ X)، والخلية المجاورة مجموعها 1 (فردي لـ O) مما يحقق التناوب التلقائي أفقياً ورأسياً.
2. المستطيل المفرغ (#) if (r == 1 || r == rows || c == 1 || c == cols) استخدام معامل || يكتشف إذا كانت الخلية تقع على أي طرف من الأطراف الأربعة (أعلى، أسفل، يمين، يسار).
3. الأعداد الأولية for (int d = 2; d * d <= num; d++) if (num % d == 0) { isPrime = false; break; } افتراض الأولية براية bool، واستخدام break الفوري عند أول قاسم لتوفير الوقت حتى جذر الرقم.
4. شبكة الضرب والمجاميع Rows: rowSum = 0 per i | Cols: loop j outside, loop i inside تصفير مجموع الصف rowSum = 0 في بداية كل سطر، وعكس ترتيب اللوب (تثبيت j والدوران بـ i) لحساب مجموع كل عمود.
5. الأزواج غير المكررة (Target T) for (int i = 0; ...) for (int j = i + 1; ...) بدء العداد الداخلي من j = i + 1 يضمن هندسياً أن i < j دائماً ويمنع تكرار الزوج المعكوس مثل (7, 2).
6. مصفوفة الأقطار (Trace Q9) j == i → 'D' | j < i → 'L' | j > i → 'U' القطر الرئيسي تتساوى فيه الإحداثيات (D)، وأسفله يكون رقم العمود أصغر من الصف (L)، وأعلاه يكون العمود أكبر (U).

💾 راية التأكيد (Boolean Flag) 🧠 افتراض الأولية أولاً
نعرف متغيراً منطقياً isPrime = true، معناه: "نفترض أن الرقم أولي حتى يثبت العكس بالدليل القاطع". يُعاد تعيين هذه الراية إلى true في كل دورة للرقم الجديد.

🧠 فحص باقي القسمة (Modulo Zero) ⚙️ إسقاط الراية واستخدام break
إذا كان باقي قسمة num % d == 0، فهذا يعني أن الرقم وجد قاسماً يقبل القسمة عليه!

• نستدعي break; فوراً للخروج من اللوب الداخلي لتوفير وقت المعالج، فبمجرد وجود قاسم واحد يسقط شرط الأولية ولا داعي لفحص باقي الأعداد.

مسار التتبع بالتحليل الرياضي (Row by Row Trace):
• السطر الأول (row = 4): اللوب الداخلي يدور من col = 1 إلى 4:
  - col=1: 1 + 4 = 5
  - col=2: 2 + 4 = 6
  - col=3: 3 + 4 = 7
  - col=4: 4 + 4 = 8 → المطبوع: 5 6 7 8
• السطر الثاني (row = 3): اللوب الداخلي يدور من col = 1 إلى 3:
  - col=1: 1 + 3 = 4
  - col=2: 2 + 3 = 5
  - col=3: 3 + 3 = 6 → المطبوع: 4 5 6
• السطر الثالث (row = 2): اللوب الداخلي يدور من col = 1 إلى 2:
  - col=1: 1 + 2 = 3
  - col=2: 2 + 2 = 4 → المطبوع: 3 4
• السطر الرابع (row = 1): اللوب الداخلي يدور من col = 1 إلى 1 فقط:
  - col=1: 1 + 1 = 2 → المطبوع: 2

مسألة 9: تتبع مصفوفة الأقطار (Diagonal D, Lower L, Upper U) Part B — Question 9: Trace i=1..4, j=1..4: if (j == i) D, else if (j < i) L, else U.
كود المسألة المعطى في الشيت:
for (int i = 1; i <= 4; i++) { for (int j = 1; j <= 4; j++) { if (j == i) cout << "D"; else if (j < i) cout << "L"; else cout << "U"; } cout << endl; }
التفسير الرياضي لمصفوفة الجبر الخطي 4 × 4:
تقسم هذه الشروط الثلاثة أي مصفوفة مربعة إلى 3 مناطق هندسية رئيسية:
• j == i: القطر الرئيسي (Main Diagonal) → يطبع الحرف D.
• j < i: المثلث السفلي (Lower Triangle) أسفل القطر → يطبع الحرف L.

🧠 المفهوم الهندسي لـ Big-O
ما هو التعقيد الزمني (Time Complexity)؟
هو مقياس رياضي يعبر عن معدل نمو عدد العمليات التي ينفذها المعالج (CPU) كلما كبر حجم المدخلات n. لا نقيس الوقت بالثواني لأن سرعة الأجهزة تختلف، بل نقيسه بعدد الخطوات الحسابية الأساسية:
• التعقيد الخطي O(n): حلقة تكرارية فردية واحدة تدور n مرة.
• التعقيد التربيعي O(n²): حلقتان متداخلتان؛ اللوب الخارجي يدور n مرة وبداخله لوب يدور n مرة، فيكون الإجمالي:
Total Operations = n × n = n²

المحور 2: أسرار تحسين الأداء البرمجي (Optimization Lab) كيف تجعل الكود أسرع 10 أضعاف وتقلل استنزاف المعالج والذاكرة؟
التقنية الأولى: التحسين الرياضي بالجذر التربيعي للأعداد الأولية (d * d ≤ num)
في المسألة رقم 3، فحصنا القواسم حتى num - 1. ولكن رياضياً: أي قاسم أكبر من الجذر التربيعي للرقم يجب أن يكون مضروباً في قاسم أصغر من الجذر!
مثال توضيحي: لفحص الرقم 100: قواسمه هي: (2 × 50)، (4 × 25)، (5 × 20)، (10 × 10).
لاحظ أننا لسنا بحاجة للبحث عن 50 أو 25 لأننا اكتشفنا شركاءهم (2 و 4) مبكراً! فإذا لم نجد أي قاسم حتى الجذر التربيعي ($\sqrt{100} = 10$)، فالرقم أولي حتماً!

⚡ التحسين بالشرط: d * d <= num 🧠 توفير 90% من دورات المعالج
لماذا كتبنا d * d <= num بدلاً من d < num؟
• شرط d * d <= num يكافئ رياضياً d ≤ √num ولكن بدون استدعاء دالة sqrt() الثقيلة التي تستهلك وقتاً إضافياً في الحسابات العشرية!
• المقارنة العملية: عند فحص الرقم 97، الكود العادي يدور 95 دورة، بينما الكود المحسن يدور 8 دورات فقط (من 2 إلى 9)!
#include <iostream> using namespace std; int main() { int n = 100; for (int num = 2; num <= n; num++) { bool isPrime = true; for (int d = 2; d * d <= num; d++) { if (num % d == 0) { isPrime = false; break; } } if (isPrime) cout << num << " "; } cout << endl; return 0; }

⚡ إلغاء اللوب الثاني بالكامل 💾 مصفوفة التراكم colSums
كيف تعمل هذه الفكرة؟
• ننشئ مصفوفة colSums[10] = {0} تمثل حصالة لكل عمود.
• عندما نصل للخلية (i=2, j=3) وقيمتها 6: نقوم بإضافتها مباشرة في حصالة العمود الثالث colSums[3] += 6.
• بعد انتهاء شبكة الجدول، تكون مجاميع الأعمدة جاهزة ومحسوبة بالفعل! لا نحتاج إلا حلقة أحادية بسيطة O(n) لعرضها بدلاً من تشغيل لوب متداخل إضافي O(n²)!
#include <iostream> using namespace std; int main() { int n = 3; int colSums[10] = {0}; // مصفوفة التراكم اللحظي for (int i = 1; i <= n; i++) { int rowSum = 0; for (int j = 1; j <= n; j++) { int val = i * j; cout << val << " "; rowSum += val; colSums[j] += val; // تراكم فوري للعمود } cout << " row sum=" << rowSum << endl; } cout << "Column sums: "; for (int j = 1; j <= n; j++) { cout << colSums[j] << " "; // طباعة مباشرة في خطوة واحدة } cout << endl; return 0; }
المحور 3: حالات الحواف والحدود القصوى (Edge Cases & Boundary Validation) كيف تحمي برنامجك من الانهيار عند إدخال قيم شاذة أو غير متوقعة؟
🧠 ما هي حالات الحواف (Edge Cases)؟ ⚠️ أسئلة الفخاخ
حالات الحواف هي القيم الواقعة عند أقصى أطراف النطاق المسموح. في الشيت حُددت الشروط التالية:
• في الشطرنج: 3 ≤ n ≤ 9 → الحواف هي n = 3 (أصغر شبكة) و n = 9 (أكبر شبكة).
• في المستطيل: rows, cols ∈ [3..12] → الحواف تشمل المستطيل المربع الأدنى 3 × 3 أو الأقصى 12 × 12.
• في مسألة جمع الأزواج (Target Sum): ماذا لو لم يعثر البرنامج على أي زوج يحقق المجموع T إطلاقاً؟
معالجة حالة عدم العثور على أي زوج (Handling Empty Match Sets):
إذا لم نضع راية تحذير، فسينتهي البرنامج دون طباعة أي شيء، مما يترك شاشة المستخدم سوداء ومبهمة. الطريقة الهندسية الصحيحة هي إضافة متغير منطقي bool pairFound = false؛ إذا ظل false حتى نهاية الحلقات، نطبع رسالة واضحة: "No pairs found matching target T".

🧠 حماية المدخلات بحلقة التحقق (Validation Loop) ⚠️ فحص شروط المسألة بدقة
نستخدم حلقة while تمنع المستخدم من إدخال أرقام خارج النطاق 2 ≤ n ≤ 10. إذا أدخل رقماً خاطئاً يُجبره البرنامج على إعادة الإدخال فوراً.
#include <iostream> using namespace std; int main() { int n; cin >> n; while (n < 2 || n > 10) { cout << "Invalid n! Must be between 2 and 10: "; cin >> n; } int values[10]; for (int k = 0; k < n; k++) cin >> values[k]; int T; cin >> T; bool pairFound = false; // راية لاكتشاف حالة الحافة الفارغة for (int i = 0; i < n - 1; i++) { for (int j = i + 1; j < n; j++) { if (values[i] + values[j] == T) { cout << "(" << values[i] << ", " << values[j] << ") "; pairFound = true; } } } // معالجة حالة الحافة عند عدم وجود أي أزواج if (!pairFound) { cout << "No pairs found with sum = " << T; } cout << endl; return 0; }
